================================================================================
                    INSURANCE AGENTIC POC - ARCHITECTURE & COMPONENTS
================================================================================

OVERVIEW
--------
This is an AI-powered Insurance e-commerce search and comparison system using
multiple specialized agents that work together to understand user queries,
fetch insurance plans, score them intelligently, and provide personalized
recommendations.

Framework: Ollama (local LLM inference)
Model: Gemma 3.1B (local, open-source language model)
UI Framework: Streamlit (interactive web interface)
Data: Dummy plan database in memory + optional web scraping

================================================================================
                            EXECUTION FLOW
================================================================================

MAIN FLOW (user query → recommendations):
================================================================================

1. USER ENTERS QUERY (Streamlit UI)
   ↓
2. INTENT AGENT (agents/intent_agent.py)
   - Extracts structured intent from natural language
   - Uses Ollama + deterministic heuristics
   - Outputs: policyType, riskFactors, location, intent type
   ↓
3. QUERY ENHANCEMENT AGENT (agents/query_enhancement_agent.py)
   - Fills in missing information with smart defaults
   - Infers propertyValue, budgetPreference, userStage
   - Uses Ollama to reason about incomplete queries
   - Outputs: Enhanced query with all parameters
   ↓
4. CONNECTOR + PRICING AGENT (agents/connectors_agent.py)
   - Fetches candidate plans from dummy database or web scrapers
   - Filters by policy type, location, risk factors
   - Computes adjusted premium (includes surcharges for pets, pools, etc.)
   - Calculates value score (based on rating, reviews, coverage/premium ratio)
   - Outputs: Ranked list of plans by value score
   ↓
5. RECOMMENDATION + COMPARISON AGENT (agents/recommendation_agent.py)
   - Takes top 5 candidate plans
   - Uses Ollama to generate human-readable explanation
   - Compares plans (best value vs. best coverage)
   - Provides risk/coverage guidance
   - Outputs: Markdown-formatted recommendation text
   ↓
6. UI DISPLAY (Streamlit)
   - Shows recommended plans with details
   - Displays comparison charts
   - Shows explanations and risk factors

================================================================================
                          AGENTS IN DETAIL
================================================================================

AGENT 1: INTENT AGENT
File: agents/intent_agent.py
Purpose: Extract structured user intent from free-form natural language
Framework: Ollama (local LLM inference) + Pattern matching heuristics

Input: User query (string)
  Example: "Home insurance with pet and swimming pool in CA"

Process:
  1. Use Ollama to generate structured JSON intent
  2. Apply deterministic heuristics to fix/validate:
     - Policy type detection (home, renters, auto, health, fire)
     - Risk factor detection (pet, swimming_pool)
     - Location detection (state codes like CA, NY, TX)
  3. Validate against predefined lists

Output: Dictionary with fields:
  - policyType: str (one of: home, fire, renters, auto, health)
  - riskFactors: List[str] (e.g., ["pet", "swimming_pool"])
  - location: str (state code or city, e.g., "CA" or "Unknown")
  - intent: str (Explore, Comparison, or Buy)
  - rawQueryEcho: str (echo of original query)

Key Features:
  - Heuristic risk factor matching (pet, swimming pool keywords)
  - State code extraction using regex
  - Fallback deterministic parsing if LLM fails

================================================================================

AGENT 2: QUERY ENHANCEMENT AGENT
File: agents/query_enhancement_agent.py
Purpose: Fill in missing information and add smart defaults
Framework: Ollama (local LLM inference)

Input: Intent dict from Agent 1

Process:
  1. Pass intent through Ollama with system prompt
  2. LLM infers missing fields:
     - Property value (e.g., $300,000 for home insurance)
     - Budget preference (LowPremium, Balanced, HighCoverage)
     - User stage (JustLooking, Comparing, ReadyToBuy)
  3. Apply fallback defaults if LLM fails

Output: Dictionary with additional fields:
  - (all fields from Agent 1 output)
  - propertyValueUsd: Optional[float]
  - budgetPreference: str (LowPremium | Balanced | HighCoverage)
  - userStage: str (JustLooking | Comparing | ReadyToBuy)

Example Output:
{
  "policyType": "home",
  "riskFactors": ["pet", "swimming_pool"],
  "location": "CA",
  "intent": "Comparison",
  "propertyValueUsd": 350000,
  "budgetPreference": "Balanced",
  "userStage": "Comparing"
}

================================================================================

AGENT 3: CONNECTOR + PRICING AGENT
File: agents/connectors_agent.py
Purpose: Fetch plans, adjust pricing, and score them
Framework: Python deterministic logic (no LLM)

Input: Enhanced query dict from Agent 2

Process:
  1. Load DUMMY_PLANS from data_plans.py (or fetch from web via data_scraper.py)
  2. Filter by:
     - Policy type (home, auto, etc.)
     - Location (state code or "ALL")
  3. Compute adjusted premium:
     - Base premium + risk surcharges (pet +5%, pool +10%)
     - Budget preference adjustment (LowPremium -5%, HighCoverage +5%)
  4. Calculate value score using formula:
     valueScore = 0.4 * coverage_ratio + 0.4 * rating + 0.2 * log10(reviews)
  5. Sort by value score descending

Output: List[Dict] with enriched plans:
  - (all original plan fields from DUMMY_PLANS)
  - adjusted_annual_premium_usd: float
  - valueScore: float (0-10 range typically)

Example Plan Output:
{
  "id": "HOM_CA_1",
  "company_name": "EverSure Insurance",
  "plan_name": "Essential Home Guard",
  "insurance_type": "home",
  "adjusted_annual_premium_usd": 1052.75,  # Original $950 + $52.75 surcharge
  "customer_rating": 4.5,
  "valueScore": 7.2,
  ...
}

================================================================================

AGENT 4: RECOMMENDATION + COMPARISON AGENT
File: agents/recommendation_agent.py
Purpose: Generate human-readable comparison and recommendation
Framework: Ollama (local LLM inference)

Input: 
  - Enhanced query dict from Agent 2
  - Top 5 ranked plans from Agent 3

Process:
  1. Format plans + query as JSON payload
  2. Send to Ollama with system prompt requesting:
     - Pick top 2-3 plans for this user
     - Explain strengths/drawbacks of each
     - Provide comparison (best value vs. best coverage)
     - Give 3-4 bullets on risk/coverage considerations
  3. Return LLM-generated markdown text

Output: String (markdown-formatted recommendation text)

Example Output:
"""
## Top Recommendations for You

### 1. EverSure Insurance - Essential Home Guard
- **Annual Premium**: $1,052.75
- **Coverage**: $350,000
- **Rating**: 4.5/5 (210 reviews)
- **Strengths**: Comprehensive fire/theft coverage, 24/7 claims support
- **Drawbacks**: No flood coverage, higher premiums in wildfire zones

### 2. Pioneer Mutual - Smart Home Shield
- **Annual Premium**: $1,015.00
- **Coverage**: $300,000
- **Rating**: 4.2/5 (95 reviews)
- **Strengths**: Bundle discounts, great claims reputation
- **Drawbacks**: Higher deductible ($1,500)

## Comparison
- Best Value: Pioneer Mutual (lower premium, good support)
- Best Coverage: EverSure (higher coverage amount)

## Key Considerations
- Pet liability: Your policy covers pet-related injuries
- Pool liability: Swimming pool adds +10% to premium
- Dwelling: Covers structure and attached structures
"""

                      TOOLS & INTEGRATIONS
================================================================================

TOOL 1: OLLAMA LOCAL LLM
Framework: Ollama (http://localhost:11434/api/chat)
Model: Gemma 3.1B (1 billion parameters, lightweight)
Usage: All LLM-based agents use this for reasoning

File: ollama_client.py
Function: chat_ollama(system_prompt: str, user_prompt: str) -> str
  - Posts to Ollama HTTP API
  - Sends system + user prompt
  - Returns LLM-generated text
  - Timeout: 120 seconds

Example Call:
  response = chat_ollama(
    system_prompt="You are an insurance expert...",
    user_prompt="User wants home insurance in CA"
  )

Benefits:
  - No cloud dependency (local inference)
  - No API keys needed
  - Privacy (data stays on device)

Framework: BeautifulSoup + Requests

Purpose: Fetch real insurance data from websites (optional)

Function: scrape_insurance_data(product_types, location) -> List[Dict]

FILE: agents/intent_agent.py
Main Functions:

    Extracts structured intent from user query

    Determines policy type by keyword matching
  - _heuristic_risk_factors(text: str) -> List[str]
    Extracts risk factors (pet, swimming_pool)
  - _find_state_codes_in_text(text: str) -> List[str]
    Finds US state codes in query

Key Features:
  - Ollama-powered LLM extraction
  - Deterministic fallback heuristics
  - Risk factor detection (pet, pool)
  - State code parsing with regex

================================================================================

FILE: agents/query_enhancement_agent.py
Main Functions:
  - enhance_query(intent: Dict[str, Any]) -> Dict[str, Any]
    Fills in missing query parameters with smart defaults

Key Logic:
  - Guesses property value for home/fire insurance ($150k-$1M range)
  - Sets budget preference based on query tone
  - Determines user stage (JustLooking/Comparing/ReadyToBuy)
  - Validates all fields before returning

================================================================================

FILE: agents/connectors_agent.py
Main Functions:
  - fetch_and_score_plans(enhanced_query: Dict) -> List[Dict]
    Fetches, filters, and ranks plans

Helper Functions:
  - _matches_type(plan, policy_type) -> bool
    Checks if plan matches desired type
  - _matches_location(plan, location) -> bool
    Checks if plan available in location
  - _compute_adjusted_premium(plan, enhanced_query) -> float
    Applies surcharges/discounts to base premium
  - _value_score(plan, adjusted_premium) -> float
    Calculates composite value score

Value Score Formula:
  score = 0.4 * (coverage/premium) + 0.4 * rating + 0.2 * log10(reviews)
  - Emphasizes coverage-to-cost ratio (40%)
  - Emphasizes customer rating (40%)
  - Slightly weights review count (20%)

================================================================================
                    MODELS & MODEL PARAMETERS
================================================================================

PRIMARY MODEL: Ollama Gemma 3.1B
Name: gemma:1b (or gemma3:1b)
Parameters: 1 billion (1B)
Type: Lightweight open-source language model
Source: Google (via Ollama)

Capabilities:
  - Natural language understanding
  - Structured output generation (JSON)
  - Reasoning about insurance products
  - Comparison and recommendation
  - Multi-turn conversations

Limitations:
  - Smaller than GPT-4 (3.5B vs. 170B+)
  - May struggle with complex multi-step reasoning
  - Less training data than largest models
  - Output quality depends on prompt engineering

Prompting Strategy:
  - Clear system prompt defining role
  - Structured JSON output requests
  - Specific constraints (supported types, budget ranges)
  - Fallback to heuristics if LLM fails

Example System Prompt (Intent Agent):
"You are an Intent Understanding Agent for an insurance e-commerce system.
Extract policyType, riskFactors, location, intent from the user query.
Respond ONLY as strict JSON with specific schema.
Include 'pet' in riskFactors if dogs/cats mentioned.
Include 'swimming_pool' if pool mentioned."

UI STATE & DATA FLOW:

Streamlit Session State (Maintained Across Reruns):
  st.session_state keys:
    - search_query: User's input query
    - intent_result: Output from Intent Agent
    - enhanced_query: Output from Query Enhancement Agent
    - plans_list: Output from Connector Agent
    - recommendation_text: Output from Recommendation Agent
    - selected_plan: Currently viewed plan
    - saved_policies: User's saved plans
    - search_history: List of previous searches
    - user_feedback: Collected ratings/comments

Data Flow Per Search:
  1. User enters query in sidebar
  2. Click "Search" → triggers callback
  3. Streamlit reruns entire script with new state
  4. Query passed through agent pipeline
  5. Results stored in session_state
  6. UI renders with updated data
  7. Charts/tables update automatically
  8. User interactions trigger new reruns (tabs, sorting, etc.)

Rerun Optimization:
  - Use @st.cache_data for static data (plans, FAQ)
  - Use @st.cache_resource for expensive objects (scrapers)
  - Conditional rendering to avoid unnecessary updates
  - Session state persistence across navigation
